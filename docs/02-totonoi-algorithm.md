# ととのい値アルゴリズム

実装: [shared/src/main/kotlin/com/totonoi/sauna/shared/calculator/TotonoiCalculator.kt](../shared/src/main/kotlin/com/totonoi/sauna/shared/calculator/TotonoiCalculator.kt)

## 前提・制約

Wear OSの手首PPGセンサーはbpm(心拍数)値しか安定して取得できず、RR間隔(心拍間隔)ベースの
厳密なHRV(心拍変動性)解析には向かない。そのため、bpmの時系列だけから「ととのい」に相当する
自律神経の切り替わりを推定するヒューリスティックを独自に設計した。
**サの国/サウォッチ等の公開アルゴリズムを再現したものではない。**

## サイクルの定義

ユーザーがWear側UIで手動タグ付けした `サウナ → 水風呂 → 休憩` の並びを1サイクルとする。
サイクルに満たない端数のフェーズはスコア計算に含めない。

## サイクルごとのスコア(0〜100点、3指標の合計)

| 指標                     | 配点    | 考え方                                                                                                                                                                                                       |
| ------------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 回復速度 (recoveryScore) | 0〜40点 | 休憩開始直後の心拍数から、休憩終盤の落ち着いた心拍数(±10%)に到達するまでの時間。20秒以内で満点、180秒以上でゼロ点の線形マッピング。速い回復=副交感神経への切り替わりが早い、とみなす                         |
| 振れ幅 (swingScore)      | 0〜30点 | サウナ+水風呂中の最大心拍と、休憩終盤(終盤20%)の平均心拍との差。20bpm〜80bpmの差を0〜30点にマッピング。寒暖差による交感神経↔副交感神経の振れが大きいほど、その後の反動(ととのい)も大きくなりやすいという仮説 |
| 安定度 (stabilityScore)  | 0〜30点 | 休憩後半60%区間のbpmを単回帰し、傾きの絶対値が0.05bpm/秒以下で満点、0.5bpm/秒以上でゼロ点。乱高下せず落ち着いた状態が続いているかを見る                                                                      |

## セッション全体のスコア

```
totalScore = average(各サイクルのtotal) + cycleBonus
cycleBonus = min(サイクル数 - 1, 3) * 3点   // 2セット目以降+3点、最大+9点
```

0〜100の範囲にクリップする。

## 実装上の補足(2026-08-25時点)

- スコア計算の入力は `PhaseSegment` の心拍サンプル列で、フェーズ順が
  `サウナ -> 水風呂 -> 休憩` に揃った3区間を1サイクルとして扱う。
- フェーズ切り替えは現状ユーザー手動のため、切り替えタイミング次第で
  スコアが変動する。
- 計測時間・フェーズ別時間の表示は分単位で丸めているため、1分未満は0分表示になる。
- 短時間セッション(サンプル数が少ない)では、各指標の一部が0点寄りになり
  「ととのい値0」が出ることがある。

## チューニング指針

- 実地データが増えたら、まず「体感ととのい度」と算出値の相関を確認する。
- 相関が低い場合は、以下の順で調整する。
  1. recoveryScore の閾値(20秒/180秒)
  2. swingScore の振れ幅レンジ(20〜80bpm)
  3. stabilityScore の傾き閾値(0.05/0.5bpm秒)
- 体動ノイズが強い環境では、算出前に心拍列の平滑化(移動平均など)を追加する。

## 既知の限界・要調整ポイント

- 係数(20秒/180秒、20bpm/80bpm、0.05/0.5bpm秒 等)はいずれも仮置きの値。実測データが
  集まり次第、統計的に妥当な範囲へ調整する必要がある。
- 手首PPGのノイズ(体動アーティファクト等)によるスパイクを平滑化する前処理が未実装。
- フェーズの自動検出(心拍波形からサウナ/水風呂/休憩を推定)は将来課題。
